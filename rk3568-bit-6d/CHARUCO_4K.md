# MIPI 4K ChArUco标定与性能实施

参数在tools/calibrate_charuco_4k.py顶部：3840×2160、7×5格、格长30mm、标记长22mm、DICT_4X4_50、至少15张有效图。目标是OpenCV 4.5.x（当前虚拟机版本）；其他OpenCV版本的板布局/接口需重新验证，不要替换不同版本生成的板。

```bash
cd /home/llx/6D/src/monocular_6d_pose/tools
python3 calibrate_charuco_4k.py --generate-board
python3 calibrate_charuco_4k.py
```

图片目录：/home/llx/6D/calibration/charuco_4k/images。结果存储到其同级results/时间戳目录。输出camera.yaml、逐视图误差report.json、缩小的角点预览。检测和求解都在4K原图完成，只有预览缩小，逐帧处理避免缓存大量4K图片。空目录、分辨率不符、有效视图不足会失败，旧结果不覆盖。畸变模型使用plumb_bob，k3固定为0；鱼眼镜头应使用独立鱼眼标定模型。图片需来自相同ISP模式、焦距、裁剪、旋转及畸变校正设置，避免对已校正图像再次使用原始畸变系数。

推荐20～30张清晰、不同距离和倾角、覆盖中心和边缘的照片。均为正视或重复画面无法得到可靠标定；工具仅检查有效角点与数量，视角多样性需人工检查。用独立照片和实测距离验证；RMS不代表毫米精度。单目内参标定与机器人手眼标定是不同步骤。标定YAML尚未自动接入真实相机节点。

## 板子

生成图案区域物理宽210mm、高150mm，外加白边。打印禁止适应页面，打印后实测格长与标记长。学习阶段可哑光打印粘在平板上；精密定位推荐商家定制平整、低反光、有尺寸精度说明的ChArUco板。必须核对字典、格数、格长、marker长、ID布局及OpenCV版本，普通棋盘格或单个ArUco不能直接用于此工具。采购前先生成板图作为定制参考。

## RK3568性能路线（待板端验证）

4K 3840×2160：NV12约12.4MB/帧，30FPS约373MB/s；BGR约24.9MB/帧，30FPS约746MB/s。以上只算一遍图像有效数据，不含stride、缓存同步与重复读写，非RK3568性能实测。

优先方案：ISP主路4K用于离线标定/按需拍照，ISP缩放支路720p或1080p用于实时检测；是否可并行需检查sensor/ISP驱动及带宽。不同模式可能裁剪/合并像素，不能一律按4K比例缩放内参，最好为实际运行模式单独标定。

V4L2 NV12(M) → 直接取Y平面灰度做ArUco，必要时RGA缩放；后续RKNN要求RGB时由RGA完成NV12到RGB及缩放。DMA-BUF需驱动导出、RGA格式/stride兼容与明确缓存/生命周期管理，当前实现仍是虚拟地址路径，不是零拷贝。

小分辨率全图检测 + 原图ROI角点精修可以折中速度/精度，但需正确恢复裁剪/缩放坐标，尚未实现。单帧队列、最新帧策略、关闭调试图已在现有节点实现。先记录输入/输出FPS、丢帧、分阶段耗时、P50/P95端到端延迟、温度及误差，再调整线程/分辨率。不要未经测量强制CPU满载或超频。当前未接真实V4L2、RKNN模型，也没有板端性能结论。
