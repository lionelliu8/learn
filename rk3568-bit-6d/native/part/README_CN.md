# 十字批头业务实验

本目标来自用户实物照片：金属六角杆身、十字刀头。用户已确认总长 25 mm 含刀头，
端面对角宽 5 mm、平行边之间的高 4 mm。随后确认平直六角杆身17 mm，
刀头及过渡段约8 mm；测量精度和十字刀头详细几何尚未确认。

## 当前已实现

- `capture_part.py` 复用已验证的原生 V4L2/RGA 程序，采集无叠字的原始 4K 灰度图。
- `inspect_part.py` 在指定 ROI 内检查暗背景上的细长亮目标，保存候选框、轴线方向和二值图。
- `test_inspect_part.py` 检查空背景、旋转细长目标、圆形干扰和多个候选；不是实物检测准确率测试。
- `envelope_proxy.scad` 是更新后的 25×5×4 mm 长方体外包络。
- `build_bit_model.py` 根据 `dimensions.json` 导出六角外包络，生成物位于
  `models/bit-v01/`，包含 OpenSCAD、OBJ、STL 和模型假设元数据；单位 mm，原点在中心、X 为长轴。
  当前六角形是仿射缩放后的近似截面，保留用户给定的两个横向尺寸；
  严格正六边形若对边距为 4 mm，对角距应为约 4.619 mm，原测量精度需要后续核实。
  当前外包络未包含准确十字头，不可作为已验证的完整配准模型，也不可冒充真实 PnP 特征点。

```sh
cd /userdata/6D-native
python3 part/test_inspect_part.py
python3 part/test_bit_model.py
python3 part/capture_part.py --count 3
python3 part/inspect_part.py part/data/SESSION/images/CAPTURE.pgm \
  --roi 960 540 1920 1080 --output part/data/SESSION/inspection
```

已有相机采集进程时不要再运行采图程序。输出目录必须是新的，防止覆盖。
候选检测依赖哑光深色、干净背景；像素长度筛选只适用于目前大约 0.34 m 的场景。
它保留所有合格候选，不会擅自选出“真正零件”。头尾尚未确定；平面轴线只在 180° 模意义下输出。
当前 `metric_pose_valid` 明确为 false，不输出虚假的深度、绕轴旋转或完整 6D 位姿。

## 实验推进顺序

1. 用原始 4K 图检查实际像素大小、对焦、反光和轮廓；相机不移动、不改变原有 ISP 模式。
2. 确认总长、六角对边距、杆身长度和刀头长度，建立带测量依据的简化六角杆身模型；
   刀头形状不能只凭三张手机照片恢复为准确机械图纸，必要的形状测量要逐项补齐。
3. 在单件、平放、干净背景下验证候选定位、头尾与面内角度。该约束模式的能力边界要单独报告。
4. 取得可观测、可对应的三维特征后，再验证 PnP 与模型投影；评估绕长轴的重复外观和姿态歧义。
5. 最后再加入遮挡、多目标或学习式关键点检测，并实测 RK3568 端性能。

本批头细小、强反光，且六角杆身和十字头存在重复外观，不保证单视图能够唯一恢复绕轴角。
如需唯一角度，可考虑添加小标记、限制允许姿态、补充视角或选用更不对称的目标。
任何外加标记都必须在实验记录中声明。
