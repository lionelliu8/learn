# 实物6D位姿推进记录

主工作目录：`/home/llx/6D/native/part`。当前为实验原型，尚未完成自动、唯一、稳定的6D识别。

## 模型从哪里来

当前使用代码参数化生成三角网格，导出STL/OBJ/OpenSCAD；不是从照片精确扫描重建。
用户测量提供总长25、杆身17、头部约8、端面对角5、对边4 mm；
照片只提供六角杆身与十字头的外观信息。尖端截面比例25%是显式示意假设。
十字槽、过渡面和精确端面还未测量，当前文件属于简化模型。

## 本轮真实推进

1. `estimate_bit_pose.py`：从真实原图中的4个人工对应点，使用实际标定K/D和IPPE计算两组6D候选。
   输出XYZ、旋转向量、旋转矩阵、重投影误差和法向检查；不把最低残差的一组自动视为唯一正确姿态。
2. `view_pose_candidates.py`：将真实图、模型投影和三轴一起显示，可以直接对比两个候选。
3. `track_bit_pose.py`：小运动下的参考表面配准，再将参考点传递到PnP；有正反向与外观质量检查。
   不是从任意画面自动发现并重定位批头的完整检测器。失败帧不输出位姿。
4. `test_bit_pose.py`：已知姿态恢复、共线点拒绝、已知小平移跟踪和空图拒绝检查已在Ubuntu通过。

## 对应点与尺寸假设

实物样例来自 `samples/side01.pgm`。初始点在 `samples_side01_seed.json`：
`[[2310,705],[2310,726],[2128,727],[2128,706]]`。
这些是助手根据图像人工估计的位置，非自动关键点，也未经实物确认。
它们假定对应同一平直面的“后端两角、过渡端两角”，且沿面边界依次排列。

当前三维面宽2.5 mm来自仿射六角模型对角宽5的一半，面长17 mm来自用户杆身长度。
真实面的边长和拐角身份尚未独立测量验证；低重投影误差不能证明这些假设正确。
模型原点是全长中心，+X朝向刀头、+Z朝向本次指定的平直面外法向。
相机坐标X向右、Y向下、Z向前，单位米；输出不是机器人基座坐标。

## 实测和失败记录

单帧人工点实验：`results/manual_face_seed_v01/pose.json`。
两组候选的4点重投影RMS约0.250、0.267 px，深度分别约269.09、268.62 mm；
这些是条件于人工点和近似尺寸的求解输出，不是已经验证的真实距离或准确度。
两候选都保留，`unique_pose_validated=false`，`automatic_recognition=false`。

5张真实静态图来自 `samples/tracking-static/`。初始稀疏光流跟踪0/5通过。
更换为表面仿射ECC配准后仍0/5通过最终质量检查。
即便单向外观相关分数约0.88–0.90，正反向位置仍相差约20–21像素，
说明沿杆身的对应关系不可靠。不能靠降低阈值把这些失败帧包装成成功。
所有旧结果保留：`results/manual_tracking_static_v01` 至 `v04`。
最新日志为 `tracking-entry-last.log`。合成测试通过并不等于实物跟踪成功。

## Ubuntu操作

查看两个实物位姿候选：

```sh
cd /home/llx/6D/native/part
python3 view_pose_candidates.py
```

人工修订原图上的四点并重新求解：

```sh
python3 estimate_bit_pose.py samples/side01.pgm --calibration calibration/camera-final.yaml \
  --annotate --output "results/manual_face_$(date +%Y%m%d_%H%M%S)"
```

对于此样例（刀头在左、杆尾在右）：依次点击同一个平直面的
“杆尾上角、杆尾下角、过渡端下角、过渡端上角”。
数字1–4会显示，R重置，Enter保存，Esc取消。不要点金属高光位置代替几何角点。
看不清真实边界时应取消，而不是随意给点。

## 尚需解决

- 无标记路线：需要可重复定位的刀头/杆身特征、更准确模型与不同视角数据；必要时改善成像和漫射照明。
- 六角杆与十字头具有重复外观，唯一绕轴角可能存在物理歧义，需要显式处理对称性。
- 临时加不对称标记可以验证位姿链路，但必须清楚称为带标记估计，不可冒充无标记识别。
- 在完成实物验证前不部署自动抓取，不将现有候选视为已经完成的业务识别系统。
