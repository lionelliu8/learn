# RK3568性能版本

目标是降低处理延迟、避免积压、在精度可接受时提高吞吐，使用率100%本身不是优化指标。

已实现：可切换OpenCV/RGA resize、复用输出图像缓冲、BGR8输入共享、图像订阅队列深度1、按订阅者启用调试绘图，以及逐帧预处理/检测/后处理耗时日志。RGA错误会报错，不会静默使用CPU伪装加速。

## 板端编译

需要Ubuntu/ROS2 Humble、OpenCV contrib、cv_bridge，以及与板端内核RGA驱动匹配的librga im2d开发文件。不要从x86虚拟机复制二进制。

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release -DENABLE_RGA=ON
source install/setup.sh
ros2 run monocular_6d_pose pose_node --ros-args --params-file src/monocular_6d_pose/config/rk3568.yaml
```

如果SDK不在标准搜索路径，补充`-DRGA_INCLUDE_DIR=/你的SDK/include -DRGA_LIBRARY=/你的SDK/lib/librga.so`。此处仅支持具有`im2d.h`接口的librga；头文件、共享库与驱动必须匹配。虚拟机不包含RGA，硬件路径尚未板端编译或验证。

## A/B测量

同一视频、分辨率、输入帧率及调试开关，分别运行：

```bash
ros2 run monocular_6d_pose pose_node --ros-args --params-file src/monocular_6d_pose/config/rk3568.yaml -p use_rga:=false
ros2 run monocular_6d_pose pose_node --ros-args --params-file src/monocular_6d_pose/config/rk3568.yaml -p use_rga:=true
```

分别记录日志耗时、CPU占用、`ros2 topic hz /object_pose`、漏检率及姿态稳定性；不要同时运行两个pose_node。日志每2秒抽样显示一次处理耗时，并不是P95统计。预处理包括图像转换、验证和resize。ROS发布为异步，total不包含接收端延迟或相机曝光时间。小尺寸图像上RGA可能慢于CPU，必须在板端测量后选择。

## 正确性及边界

默认缩放640×480到320×240；检测和PnP均在缩放图像中进行，内参同步按像素中心缩放。RGA插值与OpenCV的像素采样约定可能存在亚像素差异，应以标定板实测残差验收。缩小可能损害小目标精度，应比较640×480和320×240。

真实CameraInfo必须与图像分辨率、frame_id一致，使用plumb_bob模型；标记尺寸需要实测。当前缓存CameraInfo，适用于固定相机标定，不支持动态变焦参数的逐帧时间同步。

当前RGA实现使用ROS图像CPU虚拟地址，每次包装缓冲，不能称为DMA-BUF零拷贝。CPU仍负责ArUco与PnP；没有RKNN模型，所以NPU不参与。下一步高性能路径需要实际板端的V4L2格式、DMA-BUF导出能力、librga版本和RKNN关键点模型：V4L2 DMA-BUF → RGA颜色转换/resize → RKNN NPU → CPU PnP。当前ROS图像接口无法直接保留跨进程DMA-BUF，不能声称已实现这条完整零拷贝链。

调试图默认关闭，打开需`-p publish_debug:=true`且有订阅者。队列1减少积压，但不保证摄像头驱动内部没有缓存。尚未测量真实板端FPS、功耗或温度，不能据此宣称用满RK3568性能。
